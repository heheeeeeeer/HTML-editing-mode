# HTML Editing Mode

Add an editing layer with the least invasive changes possible. Preserve the original visual language, responsive layout, animations, navigation, and page logic.

## Inspect first

- Identify whether page content is static HTML or generated by a script. Attach the editor only after generated content exists.
- Identify the real navigation, fullscreen, and interactive controls. Do not turn them into editable or draggable targets.
- Preserve user changes already present in the worktree.

## Editing behavior

- Toggle editing with a dedicated editor action. In edit mode, visibly but subtly mark editable text and images; remove all marks when it is off.
- Make titles, body copy, labels, and card copy directly editable. Use a stable generated ID for each editable node if persistence or export needs a mapping.
- Let a selected text node expose a separate text-style panel with font size and text color controls.
- Let image clicks in edit mode replace an image URL.
- Provide a separate global color panel for CSS custom properties. Name every color by purpose, such as page background, main text, accent, or outline. Only the color swatch itself should open the browser color picker.
- Support free dragging only for independent text blocks and component containers. Exclude nested children when their parent is draggable to prevent competing drag behavior. Persist displacement as an offset layered over any pre-existing transform.

## Editor menu

Use a subtle fixed editor menu at the bottom-left unless the user specifies another position.

- Use a small circular center control containing `+`. On open, rotate it into `×`, apply a soft pink background, and scale it to about `1.3`; restore it on close.
- Reveal four comfortably spaced icon buttons in a quarter-circle above and to the right: pencil for edit mode, download for HTML export, `A` for text style, and palette for global colors.
- Give secondary icons slightly lower opacity than the center control. Use large, non-overlapping hit targets and resolve click actions via the closest button, so clicks on nested SVG paths work.
- Show a short tooltip after a deliberate hover delay, but hide it immediately on pointer exit. Position every tooltip to avoid its neighboring icons.
- Close text/color panels when the user clicks outside the panel and editor menu. Keep panels narrow and positioned above the menu so they never cover its buttons.

## Persistence and export

- Do not use local storage unless the user explicitly requests it. If the user asks to remove stored edits, delete the known editor storage keys once before restoring state, then remove or disable the local-save UI.
- Export a standalone HTML file containing the current text, image URLs, colors, and layout offsets. Strip editor controls, edit attributes, outlines, and panels from the exported document.
- Keep the original page's basic navigation or presentation logic in the export. Inline local styles when practical; do not let a source-generation script overwrite the exported current DOM.

## Validation

- Verify JavaScript syntax and check the diff for whitespace errors.
- Test the editor control, all four icon buttons (including clicking their icon centers), panel dismissal, text editing, color-swatch behavior, image URL replacement, dragging, and export.
